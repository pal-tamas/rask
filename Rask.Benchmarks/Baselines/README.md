# Rask Benchmark Baselines

Reference numbers from the live-render diff codec. Each future PR touching the
render path should compare against these and quote the delta in its description.

Hardware: Apple M4 Pro (Arm64), 14 logical / 14 physical cores, .NET 10.0.5,
BenchmarkDotNet v0.14.0, Concurrent Server GC.

## Headline metric — `payload-bytes.csv`

The bar that decides whether Rask is a real competitor to Blazor:
**bytes shipped per `StateHasChanged` for a known scenario.**

Generated by:

```
dotnet run -c Release --project Rask.Benchmarks -- payload-bytes
```

### Current numbers (default `LiveDiffMode.Auto` on both Server and WASM)

| Scenario             | Full payload | Diff payload | Diff ops |   Reduction |
|----------------------|-------------:|-------------:|---------:|------------:|
| CounterOnLargePage   |     102,763  |          57  |        1 |   **1,802×** |
| KeyedList100Reorder  |      12,406  |         205  |        4 |       **60×** |
| TextNodeUpdate       |     102,546  |          66  |        1 |   **1,554×** |
| AppendRowToList100   |      12,530  |         184  |        1 |       **68×** |

All four scenarios beat the plan's targets:

- `CounterOnLargePage`  target ≤ **200** bytes  → **57**  ✓
- `KeyedList100Reorder` target ≤ **500** bytes  → **205** ✓
- `TextNodeUpdate`      target ≤ **100** bytes  → **66**  ✓
- `AppendRowToList100`  (new) — structural insert with HTML fragment payload ✓

The "diff payload" column is the byte count of
`LivePayload.BuildPayloadUtf8Diff` output for the same state transition. The
codec lives in `Rask.Core/Live/{RenderFrame,FrameDiffer,SessionRenderCache}.cs`
and is tested in `Rask.Core.Tests/Live/{RenderFrame,FrameDiffer,SessionRenderCache}Tests.cs`.

### What ships now

- **Server** (`Rask.Server.LiveSession`) and **WASM** (`Rask.Wasm.WasmLiveSession`)
  default to `LiveDiffMode.Auto` since the AddRask/WasmHostBuilder options shape
  landed. Apps that want pre-codec behaviour explicitly opt out via
  `services.AddRask(o => o.DiffMode = LiveDiffMode.DisabledFull)` or the matching
  `WasmHostBuilder.CreateDefault(...)` callback.
- The choose-smaller heuristic ships the diff when its bytes are <= 25% of the
  rendered HTML (a conservative bound; full-payload bytes are ~2× HTML after
  JSON-escaping). Outside this window the full-HTML payload ships and the diff
  is discarded.
- `Rask.Server/Resources/rask.js` and `Rask.Wasm/Resources/rask.wasm.js` both
  carry the `applyDiff(ops)` interpreter — `SetAttribute`, `RemoveAttribute`,
  `UpdateText`, `InsertSubtree` (with HTML fragment), `RemoveSubtree`.
- `HtmlSerializer` captures per-frame UTF-16 byte offsets so `InsertSubtree` ops
  carry the corresponding HTML slice from the new render's output — structural
  changes (new rows, page-content toggles) now diff successfully.

### E2E validation

```
ServerExampleTests   (Auto, default):  164/164  ✓
WasmExampleTests     (Auto, default):  266/266  ✓
... (430/430 e2e total across both runtimes)
```

**Both runtimes pass the full Playwright smoke suite under `LiveDiffMode.Auto`.**
Four correctness fixes were essential:

1. **`_forceFullHtmlNextRender` grace flag on `LiveSession`**: keeps the
   await-resume render after a `jsInvokes`-bearing render on the full-HTML path
   so the cache rotation lines up with the client DOM across async JS interop.

2. **`diffPathEntered` gate in both `LiveSession` and `WasmLiveSession`**: when
   the diff path was entered (cssText/etc. gates passed) but the diff was
   skipped because the byte threshold or supported-ops gate rejected it, the
   fallback `SessionRenderCache.Snapshot()` would *double-rotate* —
   `TryComputeDiff` already rotates internally. Result: `_previous=null` on
   the next render, silent NRE inside `DispatchAsync`'s catch, empty payload.
   Fix: only `Snapshot()` in the fallback when `TryComputeDiff` was not invoked.

3. **`HeadAssetRegistry.AddOne` frame-leak fix**: head-asset components render
   to HTML via `Component.ToHtml()`, which calls `HtmlSerializer.Serialize`,
   which emits frames into the ambient `FrameSinkScope`. Without isolation,
   App-level `Head` contributions (Title, Meta, Link, …) leaked into the
   *main* frame stream at the top level, shifting every diff path index by N
   (counter-update path showed `[6, ...]` instead of `[1, ...]`). Fix: push a
   `null` FrameSinkScope around the asset's `ToHtml()` call.

4. **Client `resolvePath` filters to DOM-relevant node types**: browsers
   materialise top-level `<!-- ... -->` comments in the WASM `index.html`
   shell as comment nodes (`nodeType 8`) in `document.childNodes`. The
   server's frame walk only emits Element / Text / Raw / Doctype frames, so
   raw index-into-`childNodes` misaligned by the comment count. The client
   now walks `childNodes` filtering to `{1, 3, 10}` so paths match the
   server's frame model exactly.

### Defaults

- **Framework default:** `LiveOptions.DiffMode = LiveDiffMode.DisabledFull`. Bit-for-bit
  unchanged behaviour for any app that uses `AddRask()` today.
- **Example apps:** `Rask.Example.Server` and `Rask.Example.Wasm` both explicitly opt
  in to `LiveDiffMode.Auto` in their `Program.cs` so the showcase apps demonstrate
  the byte-savings to anyone running them locally or visiting the deployed pages.
- **Opt-in:** consumer apps flip the static field at startup, or set
  `RASK_DIFF_MODE=Auto|Forced` in the environment when launching `Rask.Example.Server`
  to override the example's default.

### What's NOT yet shipping

- `LiveDiffMode` config via `services.AddRask(o => o.DiffMode = ...)` — the toggle is
  a static `LiveOptions.DiffMode` property today. A proper DI shape belongs in the
  PR that flips the framework default to `Auto`.
- Navigation (`historyUrl != null`) routes to full HTML. Cross-route diff is
  achievable but the morph path handles head/title transitions for free; the diff
  path would need to carry those too.
- Out-of-band side effects (`auth`, `download`, `cssText`/`jsText` hash bumps,
  `jsInvokes`) force the full-HTML path. The diff wire format would need to
  carry those for the diff path to dominate when those are flowing.

When (a) the DI shape lands and (b) Auto becomes the framework default, the headline
claim flips from "opt-in but available everywhere the example runs" to "shipping by
default" and the README updates to cite this CSV.

## Phase 2 micro-optimisations (allocation/CPU)

Five of the eight planned micro-wins are landed; the remaining three are larger
refactors or observability-only. All ship unconditionally (no flag gate).

| # | Item | Status | Where |
|---|------|--------|-------|
| 1 | `Text` / attribute encoding fast-path (skip `HtmlEncoder` for plain ASCII) | ✓ done | `HtmlSerializer.AppendEncoded` |
| 2 | Scope poppers as `ref struct` (3 popper classes → 1 `ContextScope`) | ✓ done | `LiveRenderContext.cs` |
| 3 | `ScopedCssRegistry` lock-free read cache (`ConcurrentDictionary` front) | ✓ done | `ScopedCssRegistry.TryRegister` |
| 4 | Skip scope push/pop for handler-free cached subtrees | deferred | needs `_cachedRenderResult` metadata |
| 5 | Single-pass UTF-8 write in `BuildPayloadUtf8Spliced` (eliminate 2nd rent) | deferred | first-render-only win; diff codec dominates incremental |
| 6 | Coalesce-loop budget telemetry + worst-case bench | deferred | observability-only |
| 7 | Children-indexer specialisation (drop `.Select(c => (Child)c)`) | ✓ done | `Component[IEnumerable<Component>]` |
| 8 | Handler-id `string.Concat` cliff (prebake 1024 + stackalloc overflow) | ✓ done | `Component.RegisterHandler` |

## Allocation / throughput benches

BenchmarkDotNet outputs live in `BenchmarkDotNet.Artifacts/` after each run. Pin
the most-recent baseline as plain text here so they survive across reruns.

Suggested capture commands (run before any code change in this perf pass):

```
dotnet run -c Release --project Rask.Benchmarks -- --filter '*HtmlSerializerBenchmarks*'
dotnet run -c Release --project Rask.Benchmarks -- --filter '*LiveRenderRoundTripBenchmarks*'
dotnet run -c Release --project Rask.Benchmarks -- --filter '*LivePayloadUtf8Benchmarks*'
dotnet run -c Release --project Rask.Benchmarks -- --filter '*PayloadBytesPerUpdate*'
```

A quick smoke run (`--job short`) over `PayloadBytesPerUpdate` produced:

| Method              |     Mean | Allocated |
|---------------------|---------:|----------:|
| CounterOnLargePage  | 258 µs   |  999 KB   |
| KeyedList100Reorder |  39 µs   |  195 KB   |
| TextNodeUpdate      | 261 µs   |  997 KB   |

`Allocated` includes the per-iteration tree build (List<Child>, components,
attribute dictionaries) + the payload build. The wire-bytes column above is the
subset that actually leaves the process.
